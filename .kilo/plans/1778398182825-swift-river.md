# GidiFerry - Missing Features & Completion Plan

## App Overview
GidiFerry is a React Native ferry booking app for Lagos waterway commuting with two user roles:
- **Commuters**: Book trips, view live vessel map
- **Operators**: Scan passenger QR codes, trigger vessel departure

## Current State Analysis

### Implemented
- Auth flow (role selection, safety profile)
- Basic navigation (conditional stack)
- Trip search & booking (mock data)
- Live vessel map
- QR scanner for passenger check-in
- Departure trigger
- Database schema (WatermelonDB) - defined but not integrated
- Safety logic (night ban, capacity limit)

### Major Gaps Identified

### Phase 1: Core User Experience (Weeks 1-2)

## Notes

- The app currently uses **mock data** exclusively. Phase 1 priority is to integrate WatermelonDB.
- **React Query** is installed but unused - should be added for server state synchronization.
- **No state management** beyond Context - may need for complex booking flows.
- **No icons** currently - need vector icons library.
- **No QR code generation** - need library for ticket display.
- **No camera for commuters** - only operators scan; commuters may need camera for SOS photos.
- **No push notifications** - critical for trip updates.
- **No GPS tracking** for vessel location updates (currently static).

---

## Estimation

Based on the gaps identified, the app is approximately **30-40% complete**.

To reach MVP (Phase 1 + core Phase 2), expect:
- **~15-20 new screens/components**
- **~8-10 weeks** for a single experienced developer
- **Database integration** is the largest technical dependency
- **Navigation restructure** (stack → tabs) is blocking for UX
